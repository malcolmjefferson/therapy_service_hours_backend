# ADR-0001: RDS IAM authentication for database access

- **Status:** Accepted · **Date:** 2026-10-09 (accepted 2026-10-10) · **Deciders:** project owner
- **Related:** NFR-SEC-01, NFR-SEC-04, NFR-COST-01 · Tickets: S0-07, S0-08, S0-09, S11-03

## Context

The API Lambda runs in private subnets with **no internet and no NAT** (budget guard). Fetching a database password from Secrets Manager would need either a NAT Gateway (about $33/month each) or a VPC interface endpoint (about $7/month per AZ per endpoint). Both are disallowed without approval. Passwords also need rotation and must not appear in code.

## Decision

The application connects to PostgreSQL with **RDS IAM authentication**.

- The Lambda role has `rds-db:connect` for **specific database users only**.
- The auth token is signed **locally** by the AWS SDK (no network call), valid 15 minutes, and used as the password. Refresh the token when the pgx pool opens new connections (`BeforeConnect` hook).
- TLS is required (`sslmode=verify-full`, RDS CA bundle embedded in the binary).
- Two database roles, both with `rds_iam`: **`app_rw`** (DML only, no DDL) and **`migrator`** (DDL, used only by the migration Lambda).
- The RDS master secret is generated by RDS into Secrets Manager. It is used **once**, by a bootstrap custom resource, to create the two roles. The bootstrap resolves the secret via a CloudFormation dynamic reference at deploy time, so no runtime Lambda needs to call Secrets Manager.
- Connection pool is small (max 2 per Lambda instance) and the API Lambda has a **reserved concurrency cap** to protect the instance's connection limit (`db.t4g.micro`).

## Alternatives considered

| Option | Why not |
|---|---|
| Secrets Manager password fetched at cold start | Requires NAT or an interface endpoint. Violates budget guard. |
| Password in Lambda environment variable | Secret in plain configuration; rotation burden. |
| RDS Proxy | About $15/month per environment; violates budget guard. |
| Public database with allowlist | Violates NFR-SEC-04 (DB in private subnets). |

## Consequences

**Positive:** no stored runtime credentials, no rotation job, least privilege per function, works with zero internet.
**Negative:**
- IAM auth has a connection-rate limit (about 200 new connections/second); acceptable at this scale.
- Local development cannot use IAM auth; use a plain-password Postgres container (Testcontainers) and keep the connection code behind one interface.
- The bootstrap step adds a custom resource that must be idempotent.
- A leaked 15-minute token is usable until expiry; mitigated by private subnets and security groups.

**Cost:** $0 added.

## Validation

- Integration test: connection helper refreshes the token on a new connection after expiry (clock injected).
- Smoke test in dev: authenticated API call reads a row.
- Check: `app_rw` cannot `CREATE TABLE` (negative test, S11-03).
- Check: no `rds-db:connect` on `*`.
